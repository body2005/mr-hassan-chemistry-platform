# إصلاحات 2026-10-12

## السلوك النهائي

- الدرجة الكلية هي متوسط نسبة الاختبارات ونسبة الواجبات بوزن متساوٍ. نسبة كل نوع هي متوسط نسب عناصره المؤهلة المنشورة، وكل عنصر له وزن متساوٍ مهما اختلف عدد الأسئلة أو الدرجة القصوى. النوع الغائب لا يدخل الحساب. غير المحلول يساهم بصفر دون كتابة درجة نهائية؛ اعتماد النتائج للطالب يحتفظ بسياساته السابقة. مثال 100% اختبارات و0% واجبات =50% إجمالي. هذا يصحح معادلة النقاط الموصوفة في تسليم 2026-10-11.
- للدروس حقول بداية ونهاية منفصلة للتاريخ والوقت بتوقيت مصر، وخيار التقويم والإشعار، وخيار مسودة. النهاية تمنع الوصول للطالب عبر السياسة المشتركة، مع بقاء معاينة المدرس. لا مدة حل للفيديو. الترحيل الجديد يترك الدروس القديمة مفتوحة النهاية ويحتفظ ببياناتها.
- الفيديو يستخدم سجل المتصفح داخل الصفحة التي فُتح منها؛ Back يعيد القائمة وForward يعيد الفيديو، وتغيير فيديو قائمة التشغيل لا يضيف قوائم وسيطة. إزالة رقم المحاولة من نص قائمة التصحيح فقط.
- طلبات bootstrap المتزامنة تشترك في العملية كاملة، بما فيها تثبيت هوية الحساب. مهلة bootstrap وحده 90 ثانية للسيرفر البطيء؛ أخطاء تبديل الحساب و401 لا تُسجّل كعطل اتصال جديد.
- فحص وجود الملف الخاص بعد التوثيق وقبل إصدار video token، والتفريق بين ملف مفقود404 وعطل تخزين503، مع رسالة تنزيل المرفق المناسبة. لا استرجاع لملفات القرص المؤقت بهذه التعديلات.
- التخطيط يبدأ بعمود واحد ثم يتوسع عند768 و1024. جدول المتابعة يتحول لبطاقات حسب مساحة الحاوية، وصفحة الدفع تتكدس تحت1024، مع حقول المواعيد وأزرار اللمس44px والعنوان الطويل والمشغل والنوافذ. حافظنا على خط Cairo وألوان المنصة.

## التحقق الفعلي

- `npm run test`: **267 اختبارًا نجح** في41 ملفًا. تم تحديث اختبارات Toast القديمة إلى عقد5/10 ثوانٍ وأربع رسائل الموثق مسبقًا، واختبار تحديث التقييمات لينتظر مهلة تجميع الأحداث300ms؛ لم يتغير تنفيذ هاتين الميزتين.
- `npm run build`: نجح TypeScript وبناء Vite.
- `npm run lint`: صفر أخطاء، سبعة تحذيرات موجودة مسبقًا.
- API: **31 اختبارًا نجح** في النسب ومواعيد الإتاحة ونطاق التقييمات والتخزين وحماية الفيديو، ومنها اختبار ترحيل الدروس القديمة. اختبارات SQLite وstorage doubles معزولة؛ ليست تحققًا من حساب R2 حي.
- المتصفح: **20 اختبارًا نجح** لصفحات الحسابين الأساسية عند320/360/375/390/412/430/768/1023/1024 وبعرض أفقي850px، مع Back/Forward لكليهما. اختبارات العرض تستخدم بيانات API ثابتة ومعلنة، وتنتظر العناوين الفعلية وتفحص حدود العناصر المرئية حتى لا يخفي overflow:hidden خلل العرض. كما نجحت24 حالة سابقة للصفحة العامة بالعربية والإنجليزية.
- `alembic heads`: رأس واحد `f9e1b3d5a7c9`. لم يُشغّل الترحيل على قاعدة الإنتاج أثناء هذه الاختبارات.

## التحقق على الخدمات المنشورة — تحديث لاحق في اليوم نفسه

- تم ربط Render بحاوية R2 خاصة، مع تعطيل الوصول العام. تم تدوير بيانات الوصول المكشوفة وإبطال القديمة، ونجح فحص القراءة والكتابة والحذف. لا توجد أسرار في هذا التقرير.
- يعمل معالج الفيديو على جهاز المستخدم داخل Docker، مع اتصال PostgreSQL الخارجي وتخزين R2. نجح فحص المعالج وتم تفعيل معالجة الفيديو؛ الرفع المباشر من المتصفح إلى R2 معطل.
- رُفع فيديو اصطناعي 1080p وPDF من واجهة المدرس، وأُنتجت ست جودات فعلية من144p إلى1080p. زر المشاهدة يظهر بعد الجاهزية، وأثناء المعالجة يظهر التقدم.
- نجح التشغيل وتنزيل PDF مطابق للأصل قبل إعادة تشغيل خدمة Render وبعدها. حُذفت مسودة اختبار المدرس بعد موافقة المستخدم.
- نجح الاختبار من جلسة طالب وفرها المستخدم دون تغيير كلمة مروره: إخفاء المسودة، الظهور التلقائي بعد النشر، تشغيل1080p وتبديل فعلي إلى144p، وتنزيل PDF مطابق للأصل. نجحت أسهم الكيبورد مع إظهار مقدار الرجوع، وBack/Forward أعادا القائمة والمشغل.
- ضبط بداية مستقبلية حجب الدرس التجريبي عن الطالب، وكذلك نهاية منقضية. هذه تجربة قبل البداية وبعد النهاية، ولا تثبت اختبار إشعار عند حد دقيقة فعلية. أُعيد الدرس التجريبي لمسودة مخفية بلا مواعيد أو إشعار؛ حذف هذه المسودة الجديدة ينتظر تأكيد المستخدم.
- اكتُشف تباين ضعيف في مواعيد الدرس بالوضع الداكن: استُبدل متغير خلفية غير معرّف بمتغير سطح المنصة المعتمد للوضعين.

## المتبقي خارج الكود

### توقيت إشعار الدرس — تحديث واجهة النشر

- أزيل خيار حفظ الدرس كمسودة من نموذج الرفع وتعديل النشر؛ حفظ النموذج ينشر وفق نافذة الإتاحة وبعد جاهزية الفيديو والمرفقات.
- خيار «إرسال إشعار للطلاب الآن» يرسل إشعارًا عند الحفظ إذا كان مفعّلًا. عند إيقافه ينتظر الإشعار موعد الإتاحة وجاهزية المحتوى. يبقى الموعد ظاهرًا في التقويم في الحالتين.
- احتُفظ باسم حقل API القديم `announce_to_students` للتوافق، ومعناه الآن اختيار التوقيت وليس تعطيل الإشعارات. لا تنشر هذه التغييرات المسودات القديمة تلقائيًا.
- إشعار الإضافة المبكر يفتح صفحة المقرر، ولا يمنح تشغيلًا قبل موعد الدرس أو جاهزيته. يُعاد فحص التسجيل والدفع وحالة النشر عند عرض الإشعار، ويُمنع تكراره عند تعديل الدرس أو إتاحته.
- فحص إشعارات إتاحة الدروس يعمل كل دورة صيانة (15 ثانية بدلًا من كل أربع دورات)، بعد اكتمال مهام الدورة. زمن الوصول ليس ضمانًا بالثانية ويعتمد على استمرار عمل خدمة Render.

الفيديوهات والمرفقات القديمة التي فُقدت من قرص Render المؤقت تحتاج إعادة رفع من نسخ المستخدم الأصلية. الربط الجديد يحفظ الرفع الجديد في R2؛ لا يسترجع الملفات القديمة المفقودة.

يجب بقاء جهاز المستخدم وDocker قيد التشغيل لمعالجة الرفع الجديد. الفيديوهات التي اكتملت معالجتها تُخدَّم من R2 دون اعتماد على تشغيل الجهاز.

هذه البنية تستخدم HLS خاصًا وليست DRM؛ لا تضمن منع الالتقاط أو التنزيل منعًا مطلقًا. لم يُفعّل DRM أو RLS على الإنتاج، ولم يُختبر تسليم البريد الفعلي في جولة إعداد التخزين هذه.
