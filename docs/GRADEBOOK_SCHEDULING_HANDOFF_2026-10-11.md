# الدرجة الكلية والجدولة — تسليم 2026-10-11

الفرع: `fix/queen-p0-handoff`. هذه الجولة تعديل مصدر فقط، دون اختبارات أو build أو scanners أو تشغيل QA أو migrations أو نشر على الإنتاج. لا تمثل الأمثلة أدناه نتائج اختبارات.

## الأسباب والتغييرات

- حالة المتابعة كانت تقارن نسبة تسليم الواجبات بالحد الأدنى، وكانت القيم الغائبة تتحول إلى صفر. المقارنة الآن بالدرجة الكلية القادمة من الخادم؛ أقل من الحد أحمر «تحت المعدل الأدنى»، وعند الحد أو أعلى أخضر «أعلى من الحد الأدنى»، وغياب التقييمات `—`. يتغير الحكم فور تغيير الحد، وافتراض البداية 65% ليس حدًا ثابتًا.
- المقام القديم اعتمد على وجود نتائج مصححة ومتوسطات أنواع، واستطاع استبعاد تقييم منشور لم يحل أو لم يصحح. خدمة `gradebook.py` تجمع النقاط الممكنة منذ نشر التقييم، حتى لو كان موعد فتحه مستقبلًا. المسودة أو المسحوب لا يساهم، والمنشور الذي انتهى موعده يظل ضمن السجل والحساب.
- الحساب واحد للطلاب المؤهلين بنطاق المؤسسة والمدرس والمقرر والتسجيل النشط/المكتمل واستحقاقات الدروس/الوحدات. الجاهزية وموعد فتح المحتوى لا يحددان مقام الدرجة. التقييم غير المرتبط بدروس يحتفظ بسياسة التسجيل الموجودة بالمشروع.
- المعادلة: `100 × مجموع النقاط المكتسبة / مجموع الدرجات القصوى للتقييمات المنشورة المؤهلة`. النوع الغائب لا يدخل المقام ويعرض `—`. لكل تقييم وزن واحد؛ أحدث محاولة رسمية مسلمة وفق سياسة المشروع، دون التدريب، وأحدث نسخة واجب. تصحيحات دفتر الدرجات اليدوية الأحدث تُطبّع إلى الدرجة القصوى المنشورة ولا تضيف وزنًا آخر.
- عدم الحل وانتظار التصحيح عدّادان مختلفان. عدم وجود نقطة مكتسبة لا يكتب صفرًا نهائيًا في قاعدة البيانات. الإجمالي الحالي قد يساهم فيه التصحيح الجزئي لدى المدرس، ويُوسم بأنه مؤقت عند انتظار التصحيح/اعتماد الاختبار.
- `/users` وتفاصيل الطالب وإجمالي المجموعة و`/reports/summary` وتحليلات المقرر والتصدير تستخدم المصدر نفسه. إجمالي المجموعة مجموع النقاط على مجموع المقامات، وليس متوسط نسب الطلاب. أزيلت درجات 80/82/85 وسجل المشاهدة المصطنع من نافذة الملف الشخصي.
- الملخص الجديد مقصور على المديرين؛ لا يفتح API جديدًا يكشف إجماليًا غير معتمد للطالب. سياسة إخفاء نتائج الاختبار الأصلية باقية، وأضيف حاجز اعتماد إلى مسار دفتر درجات الطالب للاختبارات.

## مسارات الجدولة

كل المسارات أدناه تحت `/api/v1`:

- `GET /quizzes`، `GET /assignments`، `GET /courses/{id}/assessments`: فلترة مركزية قبل البداية، مع فحص نطاق الوصول؛ تجميع الدروس يتم على مستوى المقرر بدل استعلام لكل تقييم. بيانات الواجب تتضمن البداية، واستجابة المقرر تحمل وقت الخادم وأقرب حد إتاحة قادم وحالة الإتاحة.
- `/quizzes/{id}/solve` و`/assignments/{id}/solve` و`/assignments/{id}/sheet.pdf`: لا أسئلة أو ورقة واجب قبل البداية. فحص الخادم يبقى المرجع، بما فيه الروابط المباشرة.
- بدء محاولات الاختبار/الواجب وتسليم الاختبار والواجب، بما فيه رفع ملف الحل: البداية مسموحة عند `now >= start`، والكتابة ممنوعة عند `now >= end`. أجل الاختبار هو الأقرب بين بداية المحاولة + مدتها ونهاية التقييم. الجدولة والبدء/التسليم تستخدم ترتيب أقفال متسقًا.
- `PATCH /quizzes/{id}/publication` و`PATCH /assignments/{id}/publication`: تعديل البداية والنهاية أو إلغاء الجدولة بإرسال null أو سحب النشر. إدارة هذه الخيارات موجودة في سجل الاختبارات وتقرأ سجلات الخادم، بما فيها المسودات. إعادة النشر تمر بفحوص المحتوى الموجودة. المحاولات والتسليمات والنتائج لا تُحذف.
- `GET /quiz-attempts/{id}/availability`: للطالب صاحب المحاولة فقط؛ وقت الخادم والأجل وإمكان التسليم، دون أسئلة أو درجات. يستخدم لتحديث المحاولة المفتوحة بعد تغيير الموعد، دون مسح الإجابات.
- نتائج الاختبارات وسجل المحاولات وتسليمات الواجب السابقة تظل قابلة للقراءة بعد انتهاء المدة مع التسجيل والاستحقاق؛ إعادة جدولة الدرس أو تغير جاهزيته لا يمحوان النتائج. سحب نشر المحتوى يظل محكومًا بسياسة الصلاحيات.
- `GET /notifications` و`/bootstrap`: استبعاد الإشعار المستقبلي قبل LIMIT، وإعادة فحص روابط الدروس والتقييمات عند القراءة. إنشاء الإشعار المجدول لا يرسل محتواه مبكرًا عبر SSE. حلقة الصيانة تلتقط الإشعارات المستحقة في دفعات 100 مع SKIP LOCKED، وترسل إشارة لإعادة القراءة من قاعدة البيانات.
- الإشعارات والتقويم الجديدة المولدة للتقييم تحمل ارتباطًا صريحًا بمعرفه. تعديل الجدولة يحدث هذه السجلات المرتبطة. لا تُستنتج هوية تقييم من عنوان إشعار قديم؛ الإشعارات العامة/التاريخية القديمة غير المرتبطة تظل سجلات مستقلة.
- إنشاء وتعديل التقويم يتحققان من ترتيب البداية والنهاية ومن إدارة المقرر، وتُقيد قوائم الطالب بالمقررات المسجل فيها. التقويم يمكن أن يعرض موعدًا مستقبليًا للتخطيط؛ هذا لا يفتح أسئلة التقييم قبل البداية.
- إتاحة الفيديو والملفات والـmanifest والـsegments والمناقشة تظل عبر سياسة `lesson_release.py`/`can_access_lesson_content`: موعد النشر + الجاهزية + المرفقات المطلوبة معًا. تغيير نشر الدرس يرسل إشارة تحديث. إشعار إتاحة الدرس يحتفظ بمفتاح منع التكرار الموجود. نموذج الدرس الحالي لا يوفر حقل انتهاء؛ لم يُخترع حقل جديد.

## الوقت والتحديث

إدخال المواعيد وتحويلها وعرضها بتوقيت `Africa/Cairo` عبر Intl، دون فرق ساعات ثابت؛ التواريخ الواعية تحفظ بـUTC. النهاية غير اللاحقة للبداية تُرفض في الواجهة وقبل الحفظ في schemas. الإشعار العام له حقل datetime-local واضح لموعد الإرسال.

إشارات SSE تحتوي معرف المقرر فقط، ثم تعيد الواجهة قراءة بيانات مصرح بها. تغير درجات طالب يرسل للمدرس/الإدارة والطالب المعني، لا لكل زملائه. تجميع الإشارات وتأخير قصير يقللان الطلبات المكررة. مؤقت أقرب حد مبني على فرق وقت الخادم؛ العد التنازلي يستخدم ساعة الخادم وperformance.now، وليس ساعة الجهاز لتقرير الصلاحية. تتوقف المؤقتات عند تغير هوية الجلسة. فوات SSE يعالج بإعادة القراءة عند الاتصال؛ وصول المهمة الخلفية ليس شرطًا لصحة قرار الوصول.

## حدود التحقق والتسليم

- تمت قراءة المصدر وdiff فقط؛ لم تشغل اختبارات أو typecheck أو build أو scanners أو متصفح QA أو التطبيق. سلامة التشغيل والتكامل والأداء البصري تحتاج تحققًا منفصلًا عند السماح به.
- لم يتغير تخزين الفيديو أو إعداد الإنتاج أو أي قاعدة حية، ولا تُحسم بهذه الجولة عوائق S3/المعالج/البنية التحتية المسجلة في التسليم السابق.
- الحفظ والرفع يحملان `[skip ci] [skip render] [skip vercel]`. لا دمج ولا force push. مطابقة SHA وحالة تخطي النشر تُذكر في رسالة التسليم بعد الرفع؛ ليست نتائج اختبارات للتطبيق.
