# خطة التحقق والتفعيل — لم تُنفذ

هذه خطة لجولة تشغيل لاحقة بعد السماح بها. كل نتيجة هنا مطلوبة وليست ناجحة بالفعل. لم تُشغّل اختبارات أو builds أو scanners أو migrations أو تجارب رفع أو بريد أو backup/restore، ولم يحدث push أو نشر في هذه الجولة.

## تحديد الإصدار

1. راجع التعديلات السابقة والجديدة معًا، مع إبقاء مشروع `pc_builder_3d_cases/` خارج النطاق. نسخة المصدر قبل الجولة محفوظة داخل `scratch/review-20261014-before/` المستبعد من Git.
2. لا تضمّن ملفات البيئة أو الأدلة الخام أو الكوكيز أو النسخ الاحتياطية. لا تنشر جزءًا يحتاج schema أو consumer غير موجودين في الإصدار نفسه.
3. بعد الإذن بعمليات Git والفحوص، وثّق SHA المرشح وdigests صور API والواجهة والعامل. لا تنسب نجاح فحوص قديمة إليه.

## المتطلبات التي تحتاج إجراءً خارجيًا

- حدد سلسلة Render/Vercel الفعلية: عنوان peer، ومن يضيف أو يستبدل XFF، وCIDRs الموثوقة. لا تستخدم `*` أو جميع الشبكات الخاصة. المطلوب حماية limiter مع تمييز عناوين الطلاب فعلًا.
- أكد خصوصية bucket وعدم وجود public URL للأصول. استخدم بيانات اعتماد منفصلة لـAPI والعامل وقارئ النسخ الاحتياطي. مثال AWS IAM لا يثبت أن R2 يطبق الصلاحيات نفسها؛ راجع قدرات المزود الفعلية.
- حدد root صريحًا لكل ملفات محلية قديمة ومصدرها المعتمد. لا تغيّر backend حيًا أو تنقل ملفات عند startup تلقائيًا.
- احسم موضع اكتشاف السر القديم وRuleID بدليل redacted، ثم جهّز الانتقال والإبطال إذا ثبت أنه credential. لا ترسل قيم الأسرار في المحادثة.
- جهّز مرجعًا بشريًا مستقلًا لـmixed PDF وDOCX وصور الأسئلة. لا تولّد expected من مخرجات parser.
- اعتمد مرسل البريد وDNS إذا أردت تفعيل الاستعادة البريدية. يمكن إبقاء `EMAIL_ENABLED=false` بوضوح إذا تقرر تأجيلها.

## الفحوص المعزولة بعد الإذن

- راجع syntax/types/imports، ثم شغّل اختبارات API والواجهة المناسبة. عُدلت توقعات مصدر بعض اختبارات الدرجات للعقد الجديد؛ لم تُشغّل.
- تحقق من المعادلة: 5/43 = 11.63% و1/101 ≈ 0.99%، والفئة الغائبة، وعدم تكرار وزن المحاولات، وsnapshot maximum، والمنشور المستقبلي والمنتهي، والمسودة وسحب النشر وإعادته. قارن المتابعة والتفاصيل والتحليلات والتصدير وملخص الطالب.
- تحقق من الفرق بين صفر معتمد، وتسليم ينتظر التصحيح، وتقييم لم يُحل. لا يكشف API أو notification أو SSE أو summary أو export درجة غير معتمدة. إعادة فتح التصحيح تسجل السبب والقرار القديم وتحتاج اعتمادًا جديدًا.
- اختبر login/register/refresh/logout وCSRF وOrigin/CORS وexpiry وreplay وتغيير/استعادة كلمة المرور وتبديل الحساب. لا credentials في browser storage أو JSON. لا أحداث من اتصال SSE سابق ولا cache من الحساب السابق.
- تحقق من reload مع `lms_cached_user` قديم أو معدل يدويًا: لا تظهر هوية مسجلة قبل رد السيرفر. اختبر عزل history وجداول الإشعارات المحلية بين حسابين، وعدم إسناد المفاتيح القديمة غير المنسوبة لأي حساب جديد. مصدر `privateCacheIsolation.test.ts` أضيف ولم يُشغّل.
- نفذ مصفوفة guest/student/teacher/colleague/admin ومؤسستين، تشمل التفاصيل والقوائم والملفات والتسليمات والنتائج والتحليلات والتصدير والتعليقات وSSE. لا تستخدم ادعاء وصول سابق دليلًا على الاختبار.
- تحقق من HTML في عناوين وأسئلة نافذة الطباعة، ومن CSV يبدأ بـ`=`, `+`, `-`, `@` مع مسافات أو control characters. راجع مساري Excel وWord الفعليين أيضًا.
- ابنِ صور المرشح في بيئة معزولة. صورة backup تحتاج `BACKUP_API_IMAGE` بالdigest وpg_dump متوافقًا مع PostgreSQL. بناء native يشغّل اختبارات upstream؛ لا يجوز تشغيله خفية في جولة تمنع tests/builds.
- راجع المصادر الرسمية الحالية للتنبيهات، ثم نفذ audit/scan مأذونًا للصورة والـlockfiles الفعليين. أبقِ severity لكل finding التاريخي حتى وجود دليل محدد، ولا تستخدم suppression أو تغيير رقم حزمة لتجميل النتيجة.

## schema والتراجع

راجع سلسلة Alembic كاملة، ومنها migration المحلية السابقة `d5f7a9b1c3e5` والجديدة `f6a8b0c2d4e6`، على قاعدة فارغة ونسخة معزولة من schema الحي. لا تشغيل لها على الإنتاج في هذه الجولة.

الجديدة تشمل أيضًا `video_uploads.retry_after`. اختبر ثلاث محاولات تلقائية مع backoff ثم retry صريحًا لنفس المصدر قبل انتهاء نافذة48ساعة، دون طلب نقل الملف ثانية. اختبر checksum mismatch وانتهاء الاحتفاظ والإلغاء والتنظيف وطلبات retry المتزامنة وحدودها؛ لا ترفع TTL لمعالجة إخفاق غير مفهوم.

جدول heartbeat إضافي ولا يفعّل RLS أو DRM. rollback للكود يستطيع تركه. downgrade الخاصة به تحتفظ بالجدول؛ ليست استعادة لقاعدة قديمة، وupgrade تتسامح مع الاحتفاظ به. يجب التحقق من التوافق مع الكود السابق قبل cutover.

ترتيب التفعيل المأذون لاحقًا: نسخة احتياطية متحقق منها، ثم schema إضافية، ثم API والعامل المتوافقان، ثم الواجهة. تظل `VIDEO_DRM_REQUIRED=false` و`VIDEO_DRM_PACKAGING_ENABLED=false` و`VIDEO_DRM_PROVIDER=disabled`. لا database downgrade مدمر؛ استخدم stores جديدة وخطة cutover مستقلة عند الحاجة.

## التخزين والنقل

ابدأ بفحص مأذون فعلي لكتابة/قراءة/حذف probe خاص، ثم أثبت أن API والعامل يريان objects نفسها بعد إعادة التشغيل والنشر التجريبي. وجود متغيرات S3 لا يكفي.

خطط نقل نسخة غير إنتاجية أولًا:

```text
python -m scripts.migrate_private_storage --local-root <explicit-root> --journal <private-path-outside-git>
```

قبل `--apply --writers-stopped` أوقف كل الجهات الكاتبة: API والعامل وcleanup والجدولة والبريد وأي scripts، وأنهِ أو ألغِ مهام الفيديو النشطة. العلم إقرار من المشغل وليس آلية إيقاف. الأداة تنسخ وتتحقق من الحجم وSHA-256 ثم تبدل مراجع DB معًا، دون حذف الأصل أو الملفات غير المرتبطة. عند conflict أو missing أو checksum mismatch لا تُكتب فوق الوجهة.

قارن HLS allowlists والملفات والأصول والمرفقات والإيصالات والتسليمات والتقارير بعد النقل. راجع outbox وmultipart lifecycle عند المزود. لا prefix sweep عشوائي أو حذف orphan استنادًا إلى listing غير متزامن.

## الفيديو والرفع والموارد

كرر سلسلة upload/resume/cancel/retry بعد جلسات طويلة، ومن موبايل وكمبيوتر، مع network loss وتجديد الجلسة وفقد lease وتعطل التخزين وإعادة تشغيل العامل. لا تعتبر محاولة ناجحة واحدة إثباتًا لإصلاح السبب القديم. راقب RAM وdisk وmultipart وtemp؛ لم تُرفع حدود الموارد لإخفاء العيب.

استخدم مصادر أقل من360 وبدقات360/480/720/1080، وportrait/rotation وملفات بصوت وبدونه. تحقق من decode واحد وsplit/scale، وعدم upscale، وتزامن الصوت والمقاطع وkeyframes والتبديل بين الجودات.144/240 القديمة تبقى قابلة للقراءة ولا تُنشأ للفيديو الجديد.

تحقق من شريط واحد صادق حتى ready، ورسالة failure/retry واضحة، ومدة الفيديو المحفوظة قبل play. heartbeat ليس موافقة نشر، وتأخر المهمة لا يفتحها أو يقتلها تلقائيًا.

اختبر `video.buffered` والنطاقات المنفصلة، وseek إلى موضع جديد دون تحميل المسافة المتجاوزة، وABR والاختيار اليدوي وتجديد التوكن في مشاهدة طويلة. مقدار buffer يتأثر بالمتصفح والاتصال والذاكرة؛ لا وعد بعدم التقطع أو تحميل الفيديو كاملًا.

تحقق من authorization لكل manifest ومقطع ومسار بديل، وإبطال الجلسة والاستحقاق والجدولة والتزامن. legacy progressive يحتاج إعادة تجهيز مأذونة قبل منع الأصل؛ لا توقفه بإعداد DRM ناقص. اختبر العلامة المائية ومقدار التقديم/الرجوع عند320/360/375/390/412/430 وفي portrait/landscape/fullscreen وreduced-motion، دون تغطية التحكم أو تعطيل اللمس.

## Extract والمراجعة المستقلة

المرجع الحالي `apps/api/tests/fixtures/blind_inputs/reference.json` مستقل بحسب provenance المكتوب؛ لم يُعدّل أو يُولد من parser. الموجود يشمل فيزياء، ورياضيات بعمودين، وجيولوجيا، وعلوم، وأحياء PDF مصور وصورة PNG، وملفًا بلا أسئلة.

أضف mixed PDF وDOCX متنوعين بمرجع بشري قبل التشغيل، ويشمل النص والأنواع والخيارات والوحدات والصيغ والدرجات الموجودة أو الغائبة والصور ومواقع المصدر. قارن missing/extra/misclassified والأخطاء العلمية والحروف والفراغات، ولا تغيّر المرجع ليلائم output أو تستبدل كلمات حسب اسم عينة.

ربط صور Extract بالنشر وبصلاحية التقييم ما زال عمل مصدر متبقيًا. إقرار OCR لا يحقق ذلك ولا يقيس الدقة. ملف بلا أسئلة يجب أن يعيد422 دون fallback إلى أسئلة ثابتة. لا Knowledge Center أو Qdrant أو توليد AI جديد.

## البريد والمراقبة

بعد اعتماد sender/DNS، أرسل إلى صندوق اختبار مأذون فقط. رسالة طلب الاستعادة عامة، وقبول المزود لا يثبت وصول inbox. اختبر رمزًا منتهيًا أو مستخدمًا وسباق الاستخدام وتعطل المزود وretry الداخلي دون كشف وجود الحساب.

مصادر المراقبة الإدارية: `/api/v1/operations/video` و`/api/v1/operations/backlogs` و`/api/v1/ready/details`. العامة: `/health` للحياة و`/ready` للاعتمادات المطلوبة. توقف العامل لا يسقط مشاهدة الجيل المجهز. اربط الإنذارات لاحقًا بمستقبل مناسب لأخطاء API وتعطل Redis/storage وتأخر الفيديو وmail/cleanup retry ومساحة القرص؛ لم تُربط خدمة تنبيه أو بريد بهذه الجولة.

## النسخ والاستعادة

تحتاج snapshot متسقة إلى إيقاف جميع writers، وليس API وحده. جهّز volume خاصًا مشفرًا ونسخة خارج مضيف الإنتاج، ومفتاح `BACKUP_ENCRYPTION_KEY` عشوائيًا من32بايت base64 محفوظًا منفصلًا، وقارئ S3 محدودًا. لا تستخدم مفتاح جلسات API لتشفير archive.

السكربت `scripts.private_backup` يتطلب فعلًا صريحًا: `backup` أو`verify` أو`restore`. يسجل SHA وschema revisions وchecksums/metadata ويستخدم AES-256-GCM. retention30يومًا metadata فقط؛ الجدولة والنسخ خارج المضيف وpruning تحتاج إعدادًا ومراجعة مستقلين.

الاستعادة تتطلب `RESTORE_DATABASE_URL` و`RESTORE_S3_*` إلى قاعدة وbucket جديدين وفارغين. يتحقق archive قبل parsing، ولا يُعاد توجيه التطبيق الحي أثناء التجربة. بعد restore قارن schema والمدفوعات والاستحقاقات والنتائج وكل object، وشغّل الفيديو والمرفقات من stores المستعادة فقط. checksum صالح ليس إثبات تشغيل.

عند انقطاع الاستعادة تبقى targets الجديدة للمراجعة، دون مسح الأصل أو overwrite أو cleanup مدمر. لا حذف أرشيف قديم دون سياسة احتفاظ معتمدة.

## قرار الإطلاق

تظل موافقة الإطلاق معلقة على التحقق من أسرار الإصدار وتنبيهاته والعزل والاستمرارية والعامل/schema والدرجات والـproxy والتعافي، بحسب نطاق الإصدار. يمكن تأجيل DRM المدفوع وRLS الكامل والبريد غير المفعل بوضوح. لا يُعلن Extract مكتملًا قبل إغلاق فجواته، ولا تُنسب نتائج قديمة إلى التعديلات الجديدة.
