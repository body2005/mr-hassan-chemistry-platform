# معالج جودات الفيديو على جهازك

Render يستقبل الرفع ويحفظ المهمة في PostgreSQL. جهازك يسحب الملف من التخزين
الخاص، ويحوّله إلى الجودات المتاحة حتى 1080p، ويرفع الناتج إلى نفس التخزين.
الموقع يعرض «مشاهدة الدرس» بعد تأكيد اكتمال التجهيز. لا توجد حاجة لفتح منفذ
على جهازك أو توجيه الراوتر إليه. الملف الأصلي الأقل من 1080p لا يتحول إلى
تفاصيل حقيقية بدقة أعلى؛ الجودات لا تتجاوز دقة المصدر.

## الحالة الحالية

اختيار التشغيل على جهازك يوفّر استضافة معالج منفصل، لكنه يحتاج حساب تخزين
دائم متوافقًا مع S3 وبيانات اتصال PostgreSQL الخارجية من Render. الحساب غير
متوفر حاليًا؛ تجهيز الملفات أو صورة Docker لا يعني أن المعالج متصل بالموقع.
لا تفعّل `VIDEO_PROCESSING_ENABLED` على Render قبل نجاح فحص الاتصال أدناه.

## التجهيز

1. افتح Docker Desktop بمحرك Linux. اترك له قرابة 3 GiB ذاكرة و32 GiB مساحة
   عمل خالية على الأقل. شغّل PowerShell من مجلد المشروع.
2. ابنِ الصورة من نفس نسخة المشروع:

   ```powershell
   .\scripts\start-video-worker.ps1 -BuildOnly
   ```

3. السكربت ينشئ ملف `.env.video-worker.local` مستبعدًا من Git، ومفتاحًا محليًا
   للمعالج. املأ `DATABASE_URL` بعنوان **External Database URL** من قاعدة
   بيانات Render، مع `sslmode=require` أو تحقق TLS أقوى. لا تستخدم العنوان
   الداخلي الذي يعمل داخل Render فقط. ضع بيانات التخزين الخاص في مفاتيح
   `S3_*`. القيم حرفية دون علامات تنصيص. لا ترسل الأسرار في المحادثة.
   المعالج لا يحتاج مفتاح جلسات الموقع ولا مفتاح خدمة البريد.
   انسخ وجهة الدفع العامة الموجودة في إعدادات الموقع إلى `PAYMENT_BANK_DETAILS`؛
   إعدادات production المشتركة تشترطها، رغم أن المعالج لا يستقبل مدفوعات.
4. اختبر المتطلبات قبل التشغيل:

   ```powershell
   .\scripts\start-video-worker.ps1 -CheckOnly
   ```

   الفحص يختبر اتصال قاعدة البيانات وجدول المهام، وكتابة/قراءة/حذف ملف اختبار
   صغير في التخزين الخاص، وFFmpeg ومساحة العمل. لا يطبع كلمات السر أو روابط
   الاتصال. إذا منع Render اتصال جهازك، اسمح بعنوانه في إعدادات قاعدة البيانات
   عند الحاجة بعد مراجعتها، دون فتح قاعدة البيانات للعالم كله.
5. بعد نجاح الفحص، شغّل:

   ```powershell
   .\scripts\start-video-worker.ps1
   ```

6. في Render ضع `STORAGE_BACKEND=s3` ونفس إعدادات `S3_*` الموجودة محليًا، ثم
   `VIDEO_PROCESSING_ENABLED=true`. أبقِ `VIDEO_DIRECT_UPLOAD_ENABLED=false`
   للرفع المعتاد الحالي؛ تفعيل الرفع المباشر يحتاج إعداد عنوان رفع مستقل.
   ارفع فيديو اختبار صغيرًا وانتظر حالة `ready` قبل رفع الملفات الكبيرة.
   الفيديوهات المحلية القديمة في Render تحتاج إعادة رفعها إلى التخزين الجديد.

## المتابعة والإيقاف

```powershell
docker compose -p chemistry-video-pc -f infra/video-worker.pc.yml ps
docker compose -p chemistry-video-pc -f infra/video-worker.pc.yml logs --tail 40 video-worker
docker compose -p chemistry-video-pc -f infra/video-worker.pc.yml stop video-worker
```

Docker يعيد تشغيل الحاوية بعد إعادة تشغيله؛ ابدأ Docker Desktop عند دخول
Windows. نوم الجهاز أو إغلاقه يوقف تجهيز المهام حتى يعود. الفيديوهات الجاهزة
تظل في التخزين الدائم ويمكن تشغيلها دون بقاء جهازك مفتوحًا. مراقبة عملية
الحاوية وحدها لا تثبت اتصالها؛ فحص المتطلبات وفيديو `ready` هما التحقق المطلوب.
